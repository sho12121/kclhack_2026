# コメント返信とプロフィールの作成履歴

`supabase/migrations/202611060005_message_replies.sql` をSupabase SQL Editorで実行する。
既存コメント・プロフィール・掲示板は保持する。古い「参加中の掲示板に新規投稿」の通知（board_reply）だけを削除し、今後は通常投稿の通知を作らない。

## 会話

コメントの「返信する」で返信先を指定する。投稿前に返信先と本文の抜粋が表示され、「返信をやめる」で通常投稿に戻せる。送信後は返信先の作者とコメント番号を表示する。削除済み・別掲示板・存在しないコメントへの返信はDBで拒否する。参加・開始日時・ゲスト制限も引き続きDBで検証する。

返信通知（comment_reply）は返信先の作者だけに作成する。自分への返信では作成しない。フォロー・招待等の通知は継続する。返信自体を削除すると、その返信の通知も削除される。古い一斉投稿通知と新しい返信通知は種類を分けているため、SQLを再実行しても新しい返信通知は消えない。

## プロフィール

コメント履歴の取得を廃止し、共通の掲示板取得結果から本人が作成した掲示板を表示する。お気に入りも同じ取得結果を利用する。

## サンプル

ホームのサンプル切替を廃止。`?demo=1` でも実際のDB一覧を表示する。
`src/lib/sample-boards.ts` などのサンプルファイルは残す。DBに人が作成した動作確認用の掲示板は、この変更では削除しない。

## 検証

`npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。
`PGLITE_MODULE=（PGliteのエントリーポイント） node supabase/tests/replies-security.mjs` で返信先検証・本人だけへの通知・再実行・削除を検証する。
