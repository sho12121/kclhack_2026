# ゲストプロフィールと画像変更

## 操作

ログイン画面の「ホームに戻る」から一覧へ戻れる。ゲストも「マイページ」を開き、ゲスト#連番と本人が作成した掲示板を閲覧できる。ゲストにはプロフィール編集・画像選択・お気に入り編集を表示しない。サーバーもプロフィール変更を拒否し、プロフィールDBのゲスト編集制限は維持する。

通常アカウントは「プロフィールを編集」からアイコン・背景の画像を選べる。PNG/JPEG/WebP、各2MB以内。プレビューを確認して保存する。「初期アイコンに戻す」「初期背景に戻す」も利用できる。

## Supabaseへの反映

SQL Editorで `supabase/migrations/202611070004_guest_profile_images.sql` を実行する。

- 既存の表示番号を維持し、番号がないゲストにも連番を発行する。RLSで本人の番号だけを読めるようにする。
- Storageにprofile-imagesという公開バケットを用意する。画像は公開URLで表示するため、追加した画像へのリンクを知っている人は閲覧可能。
- アップロードと削除は通常アカウントの本人フォルダだけに制限する。ゲストや他人による操作は拒否する。別の広い許可ポリシーがあってもこのバケットの制約を維持する。
- 既存のプロフィール・投稿・番号を削除しない。

Storageの設計は公式の[アクセス制御](https://supabase.com/docs/guides/storage/security/access-control)と[公開バケット](https://supabase.com/docs/guides/storage/buckets/fundamentals)の仕様を使用する。管理者用の秘密キーは不要。

## 保存処理

サーバーで認証と通常アカウントかどうかを確認してから、ファイルの容量・MIME・ヘッダーを検証する。元のファイル名やクライアントから送られたURLは保存先に使わず、本人ID配下にランダムな名前でアップロードする。

保存したURLは既存のprofiles.avatar_url/cover_urlに保持する。新しいファイルでの保存に成功するまでは古い画像を削除しない。失敗時は今回アップロードしたファイルだけを削除し、元のプロフィールを保つ。画像を差し替えた後は不要になった古い画像を削除する。削除対象は自分のStorageフォルダ内だけを許可する。

2枚の画像を送れるよう、Next.jsのServer Actionの本文上限を5MBにする。画像はブラウザで直接読み、毎回サーバーで再加工しない。
