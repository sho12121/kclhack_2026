# データ保存の仕組み

## 保存先

| テーブル | 内容 | 閲覧できる人 |
| --- | --- | --- |
| profiles | ニックネーム、自己紹介、プロフィール項目 | 本人の通常アカウント |
| boards | 掲示板タイトル、映画情報、定員、開始日時、作成日時 | 全員 |
| board_members | 掲示板への参加登録 | 本人の登録行 |
| messages | 投稿者、会話本文、投稿日時 | 掲示板の参加者 |

通常アカウントもゲストも、作成・参加・会話ができます。プロフィールの編集は通常アカウントのみです。生年月日や居住地を会話参加者へ公開しません。会話には投稿時のニックネームだけを記録します。

## 初期設定

Supabaseの対象プロジェクトのSQL Editorで、`supabase/migrations/202611010001_movie_boards.sql` を実行します。既存のプロフィール行は削除しません。列・テーブル・関数を追加し、アクセス制限を設定します。

既存のprofilesに追加済みの列はそのまま使います。以前に独自の型や必須列を設定している場合は、そのスキーマに合わせる必要があります。エラー時は途中の変更を取り消すトランザクションになっています。

新しい秘密キーやservice_roleキーは使いません。アプリは既存のSupabase接続情報と利用者のセッションで接続し、DBのRLSでも権限を確認します。

## 操作の流れ

- 作成画面で確認後に保存すると、サーバーで入力を再確認し、選択映画の正しい情報とジャンルをTMDbから取得します。DBでは作成者を本人に固定し、掲示板作成と作成者の参加をまとめて保存します。同じ作成要求を再送しても掲示板を重複作成しません。
- 一覧から掲示板を開き、参加ボタンで参加登録します。DBが掲示板をロックして残り人数を確認するので、同時申し込みで定員を超えない構造です。すでに参加済みの人を二重登録しません。
- 投稿できるのは参加者で、開始日時以降だけです。1投稿は2000文字まで。投稿者IDはDBがセッションから設定します。
- 会話画面は5秒ごとに追加分を取得します。最初は最新50件を表示し、「以前の会話を読み込む」で過去の履歴も読めます。削除済みコメントのIDも同時に取得し、表示中の会話に反映します。WebSocketによる即時更新は未実装です。
- プロフィール保存はprofilesの更新に一本化しました。エラーの場合は成功扱いにせず、入力した空欄もそのまま保存します。
- 読み取りの一時的な通信失敗は1回再試行します。会話投稿は二重送信を避けるため自動再送しません。

## 通信の待ち時間を減らす工夫

- `npm run dev` は `scripts/dev-network.mjs` をプリロードします。WSLでのみ、SupabaseとTMDbへの名前解決をIPv4に限定します。A/AAAAを同時に調べると長く停止するWSL環境への対応です。localhostや他の接続先、明示的なIPv6指定には適用しません。OSのDNS設定や本番のbuild/startは変更しません。反映には開発サーバーの再起動が必要です。
- Supabaseクライアントと検証済み認証情報はReactの1回の描画中だけ共有します。別のリクエスト・利用者へ認証結果を使い回しません。Proxyのセッション更新は引き続き独立して行います。
- プロフィールと投稿履歴は同時に取得します。旧プロフィールの補助表示は検証済みJWTのmetadataを使い、Auth APIへの追加取得を省きます。保存したプロフィールは引き続きDBの値を優先します。
- 会話は参加登録を起点に、関連する掲示板の投稿を1回のAPI呼び出しで取得します。参加者の行がなければ403です。DBの会話用RLSも適用されます。
- 自分の投稿はDBが保存して返したIDを確認して画面に追加します。この時点の自分の名前は「あなた」、日時は保存応答時のサーバー時刻です。次回の会話取得でDBの正式な名前・日時に置き換えます。保存失敗時には追加しません。
- 投稿のたびに掲示板全体を再取得せず、参加成功後・作成成功後の二重の画面再読み込みも省いています。プロフィールは通常のページ遷移で開くときにDBから履歴を取得します。
- SDKの自動再試行を無効にし、アプリの読み取り用再試行（1回）に統一します。DBへの各リクエストは10秒で打ち切ります。相手の投稿の自動取得は引き続き5秒間隔です。

## 主なファイル

- `src/app/boards/actions.ts`: 作成・参加・投稿の入口
- `src/lib/boards.ts`: 募集情報と参加者向けの会話取得
- `src/components/boards/board-room.tsx`: 会話の表示・入力・定期更新
- `src/app/account/actions.ts`: プロフィールの保存
- `src/lib/profile.ts`: プロフィールの入力確認と表示用変換
- `src/lib/auth-redirect.ts`: ログイン・ゲスト利用後に戻れるURLの制限
- `supabase/migrations/202611010001_movie_boards.sql`: 保存先、権限、定員などのDBルール

通常の一覧はDBを表示します。発表時の固定サンプルは `/?demo=1` に残しています。サンプルから実際の参加はできません。

## 確認方法

1. 通常アカウントでプロフィールを変更し、再読み込み後も残ることを確認する。自己紹介を空欄に戻す操作も試す。
2. ブラウザAでゲスト利用を開始し、掲示板を作る。
3. 別のブラウザBで同じ掲示板へ参加する。開始前は投稿できず、開始後に投稿できることを確認する。
4. お互いのメッセージが表示され、再読み込み後も残ることを確認する。
5. 参加していないブラウザCから、会話本文が読めないことを確認する。

Nodeの入力検証テストは `npm test`。DBのRLS・参加人数・投稿制限は `supabase/tests/security.mjs` でも検証できます。これは本番DBに接続しません。PGliteは一時ディレクトリだけにインストールして実行できます。

```bash
npm install --prefix /tmp/hanacinema-db-check --no-audit --no-fund @electric-sql/pglite
PGLITE_MODULE=/tmp/hanacinema-db-check/node_modules/@electric-sql/pglite/dist/index.js node supabase/tests/security.mjs
```

ゲスト参加設定・フォロー・通知・本人のコメントと掲示板の削除を追加しました。追加用SQLと使い方は `docs/social-features.md` を参照してください。掲示板の編集・退会、お気に入り保存、ゲストから正式アカウントへのデータ引き継ぎは未実装です。
