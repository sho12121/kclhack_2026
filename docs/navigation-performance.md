# 画面遷移の改善（2026-11-06）

## 変更

- 掲示板の募集情報と本人のお気に入りを並行取得する。会話画面も募集情報と会話取得を並行して待ち、参加者にだけ会話を渡す。未参加者向けの会話RPCはDB側で拒否し、募集情報と参加ボタンだけを表示する。
- 作成画面では不要な掲示板一覧・お気に入り一覧を取得しない。フォームと招待候補だけを表示する。
- 主要4メニューをNext.jsの `Link prefetch={true}` で先読みする。先読みは本番ビルドで有効。先読み済みのデータはブラウザのNext Routerに保持され、ログイン・ログアウトのlayout再検証で破棄される。
- `loading.tsx` と、一覧／作成の切替時にリセットするSuspenseを追加する。先読みが間に合わない場合も読み込み中表示とナビゲーションを出す。
- ヘッダーは認証確認だけをSuspenseで囲み、ロゴ全体の表示を待たせない。
- 掲示板を開く操作を通常のNext Linkにし、リンクの先読み・別タブで開く操作を利用できるようにする。満員・未参加の場合の無効化は維持する。
- 作成フォームは必要な画面で動的に読み込む。プロフィールから使われていないサンプルポスターの描画コードを取り除く。
- 認証確認・RLSは維持。個人データの全ユーザー共通キャッシュは導入しない。SQLの追加実行は不要。

## 計測条件と結果

実SupabaseやVercel本番の実測値ではない。Next.jsの本番ビルドをローカルで起動し、PGliteと模擬Authを使い、SupabaseへのAPI呼び出しごとに150msの固定遅延を加えた。Chromiumで変更前後を同条件で比較。データは小さな固定テストデータ。表示完了は主要コンテンツが見えた時点で判断。

先読みのないURL直接表示（3回の中央値）：

| 画面 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 掲示板一覧 | 508ms | 513ms |
| 作成 | 829ms | 508ms |
| プロフィール | 657ms | 504ms |
| 通知 | 500ms | 505ms |
| 会話 | 806ms | 487ms |

主要メニューの先読みが完了してからクリックした場合（各1回）：

| 遷移先 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 作成 | 845ms | 80ms |
| プロフィール | 837ms | 71ms |
| 通知 | 857ms | 62ms |

URLを直接開く場合、先読み前のクリック、初回JS取得、DBの距離・起動待ち・通信速度によって変わる。常に0.5秒以内という保証ではない。一覧・通知の直接表示では直列処理の削減余地が少なく、今回の条件では内容表示時間の差はほぼない。先読みとloading表示は別の改善として扱う。

開発中の `npm run dev` は初めて開くルートのコンパイルがあり、先読みも本番と異なる。最終的な体感は `npm run build` → `npm run start` またはVercelへの反映後に確認する。
